# Owned Unity staging pipeline

This pipeline turns explicitly selected authored textures into native Unity
AssetBundles and validates their payloads and GPU samples. It uses Unity
6000.0.75f1, Linux build support, Vulkan, Linear color space, and the Built-in
Render Pipeline. Native GPU validation needs a working graphics device and
cannot run with `-nographics`.

## Portable project inputs

The checked-in `unity/Packages/manifest.public.json` is the minimal public
package manifest. The workstation's `manifest.json` and `packages-lock.json`
are local, ignored state and are not the contributor template.

For a fresh interactive authoring checkout, initialize the local manifest before
opening `unity/`:

```sh
cp unity/Packages/manifest.public.json unity/Packages/manifest.json
```

Unity resolves the public dependencies and creates its local lock file. Preserve
an existing workstation manifest when working in an already configured project;
use a separate checkout or generated project to test the portable template.
Do not commit local integration packages or package credentials.

## Stage and build

From the repository root with asset dependencies installed:

```sh
python tools/asset_pipeline.py
python tools/validate_staging.py
python tools/prepare_unity.py
```

Preparation builds `build/unity-project/` from an explicit template allowlist,
the public package manifest, the manifest-selected Unity DDS payloads, and their
metadata. It rejects linked ancestors, unsafe paths, resource files, unexpected
names, changed hashes, wrong color semantics, and incomplete BC3 mip chains.
No game installation is read. PNGs and top-down preview DDS files are not copied.
Preparation alone does not execute Unity or establish native validation.

Prototype entries emit albedo and a paired normal study by default. Set
`generate_normal` to `false` for an albedo-only material study. The flag must be
a JSON boolean. Preparation and bundle building copy only the roles listed in
the resulting staging manifest, so a stale unlisted normal file is not packaged.
This option does not establish that an original material's normal needs replacing.

To build that separate project with an explicitly selected Editor:

```sh
python tools/prepare_unity.py --editor /path/to/Unity
```

The command runs `MeadowsBuild.Build` with the Linux64 target and Vulkan.
Review the build log and catalog. It does not download or substitute an Editor.
Do not run another Editor against the same open project.

For the initialized interactive project:

```sh
python tools/prepare_unity.py --authoring
```

Then run **Valheim Impact > Build owned Meadows probes** in its matching Editor.
The authoring preparation stages inputs while preserving existing packages and
settings. It cannot be combined with `--editor`. Generated `OwnedInputs/`,
`Assets/Owned/`, `Assets/Probes/`, and `Bundles/` remain local.

Preparation leaves caches intact. Use a clean generated project when reviewing
template or compatibility changes. Neither the full Unity project nor its cache
is a release payload.

## Native texture contract

`MeadowsBuild.Build` strips the 128-byte DDS header and supplies every bottom-up
BC3 mip to `Texture2D(width, height, DXT5, true, !srgb)`. `Apply(false, true)`
preserves supplied mips and disables CPU readability. DXT5nm retains tangent X
in alpha and Y in green; the normal maps do not pass through a PNG normal-map
importer or get regenerated by this build script.

Each texture has its own Linux bundle and exact selector
`assets/owned/<id>.asset`. `Bundles/catalog.json` records relative bundle paths,
selectors, full-file and payload hashes, dimensions, color space, mip counts,
and payload bytes. Runtime paths resolve relative to the catalog's package
location. The runtime validates descriptors and referenced file hashes before
admitting demand.

The Editor rereads every bundle and checks its exact asset, format, dimensions,
mips, color interpretation, and non-readable state. It captures hashed base-mip
GPU samples and publishes the success catalog only after every texture passes.
A prior catalog is invalidated before rebuilding. These synchronous authoring
checks are distinct from the runtime's asynchronous loading measurements.

For interactive authoring output, run:

```sh
python tools/validate_native.py
```

This requires `requirements-inspection.txt`. It reads `unity/Bundles/` and
matching `build/staging/meadows/` payloads, validates serialization, and compares
GPU samples against independent BC3 decoding with linearized sRGB and actual
alpha. It currently does not select the separate batch project's output path.
See [native evidence](evidence/native-validation.json) for the recorded artifact
set and tolerance. It is not a total VRAM or frame-time result.

## Scene and resolution studies

The build creates daylight, sunset, and night blockout scenes with owned
geometry and fixed comparison framing. They contain material studies for
ground, timber, thatch, stone, a trunk and tree card, shoreline, simple water,
and a scale capsule. Standard materials exercise albedo and packed normals.
The card is a fixed-view study; the water has no game water shader, waves, or
refraction. These scenes are not Valheim geometry or rendering.

`tools/unity/GraniteQualityProbe.cs` provides a same-art 256-versus-1024 sampling
comparison at matched screen coverage. Its unlit comparison isolates texture
resolution while preserving the open scene and destroying its own temporary
objects. Fixed 4K captures can support visual review, but do not establish game
appearance, complete 4K quality, or preset performance.

## Validate a contribution

Python preparation checks can run without Unity:

```sh
python -m unittest discover -s tests -p 'test_prepare_unity.py' -v
```

For native changes, record the exact source and bundle hashes, Editor/API,
report, and cleanup outcome. Use the separate scheduler and binding fixtures
for async ownership or material changes; see [RUNTIME.md](RUNTIME.md) and
[UNITY_SETUP.md](UNITY_SETUP.md).

A texture readback does not prove game UV alignment, actual material coverage,
weather, LODs, or model/shader streaming. The Balanced target of 6 GB VRAM,
16 GB RAM at 1080p and crisp 4K presentation both require representative
validation. Native authoring does not deploy to the game.
